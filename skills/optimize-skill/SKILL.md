# /optimize-skill - スキルトークン最適化解析

指定したスキルのトークン使用量を解析し、削減可能な箇所を特定・改善提案します。

## 実行

`$ARGUMENTS` のスキルを解析してください。

### Step 1: 対象スキルの特定

`$ARGUMENTS` の値に応じて対象を決定：

| 入力 | 対象ファイル |
|------|------------|
| スキル名（例: `analyze`） | `.claude/skills/{name}/SKILL.md` または `.claude/skills/{name}.md` |
| `all` | `.claude/skills/` 配下のすべての `SKILL.md` と `*.md` |
| ファイルパス | 指定パスをそのまま使用 |

スキルファイルが見つからない場合は、Glob で `.claude/skills/**/*.md` を検索して候補を提示する。

### Step 2: スキルファイルを読み込む

対象スキルファイルを Read する。`all` の場合は Glob で一覧を取得してから各ファイルを Read する。

### Step 3: トークン数を推定する

以下の計算式でファイルごとのトークン数を推定：

```
推定トークン数 = ファイルサイズ（バイト） ÷ 3
（日本語混じりテキストの目安: 3バイト/トークン）
```

`all` の場合は推定トークン数の降順でランキング表示する。

### Step 4: アンチパターンを検出する

以下のカテゴリでスキルを解析し、該当箇所を特定する：

#### カテゴリA: 冗長な強調・アノテーション（削減効果: 小〜中）

| パターン | 検出方法 | 改善案 |
|---------|---------|--------|
| `（必須）` の多用 | 出現回数をカウント | 必要な箇所のみに絞る |
| `**重要**` `**必ず**` 等の過剰な強調 | 出現回数をカウント | 指示自体を簡潔にする |
| 区切り線 `━━━` の繰り返し | 出現回数をカウント | 見出しだけで代替 |
| 「〇〇してください」の連続 | 末尾パターン | 箇条書きで簡潔に |

#### カテゴリB: 過剰な例示・テンプレート（削減効果: 中〜大）

| パターン | 検出方法 | 改善案 |
|---------|---------|--------|
| 同じ概念に3件以上の例 | 類似例のブロックを確認 | 代表例1〜2件に絞る |
| Markdownテンプレートのインライン埋め込み | コードブロック内の `{変数}` 付き大型テンプレートを確認 | テンプレートを別ファイルに分離するか簡略化 |
| `使用例` セクションの過剰な列挙 | 使用例ブロックの行数 | 3件以内に絞る |

#### カテゴリC: 重複・冗長な説明（削減効果: 中）

| パターン | 検出方法 | 改善案 |
|---------|---------|--------|
| 同じ条件分岐・判定ロジックが複数箇所に存在 | 類似した表・段落 | 一箇所にまとめる |
| 「使い方」と「実行」に同じ情報が重複 | 先頭セクションと後半の対応を比較 | どちらかを削除 |
| エラーハンドリングの網羅的な列挙 | エラー系の表の行数 | よくあるケースのみ残す |

#### カテゴリD: 遅延読み込みで代替できる静的コンテンツ（削減効果: 大）

| パターン | 検出方法 | 改善案 |
|---------|---------|--------|
| 大きなスキーマ・辞書・ベンチマーク値がインライン | 固定値の大きなテーブルや定義リスト | 別ファイル参照に変更（必要時のみ Read） |
| Claudeが推論できる内容が明示されている | 「AIが常識的に判断できる」レベルの詳細仕様 | 削除または簡略化 |
| 出力フォーマットの過剰な指定 | 大型テンプレートブロック | 要点のみ残す |

### Step 5: 解析レポートを出力する

以下の内容を含むレポートを出力する：

- **概要**: ファイルパス・サイズ・推定トークン数・検出問題件数
- **検出されたアンチパターン**: 優先度（高/中/低）順に、ID・該当箇所・推定削減トークン・改善案をテーブルで一覧化。該当なしの優先度は「なし」と記載
- **改善サマリ**: 優先度別の件数と推定削減トークン合計、全体の削減率
- **推奨アクション**: 効果の高い順に具体的な手順を列挙

### Step 5.5: 今回の解析コストを出力する

レポート末尾に以下を追記する：

```
---
**今回の解析コスト（推定）**
- スキル本体（自動注入）: ~{optimize-skillのファイルサイズ ÷ 3} tok
- 解析対象スキル（Read）: ~{対象ファイルのファイルサイズ ÷ 3} tok
- 出力レポート: ~{レポートの文字数 ÷ 3} tok
- 合計: ~{合計} tok
※ 対象が optimize-skill 自身の場合は上2行が同一ファイルのため2重注入と注記する
```

### Step 6: 改善版の作成（任意）

解析完了後、修正範囲（全優先 / 一部指定 / レポートのみ）をユーザーに確認する。修正を行う場合は：
- 元ファイルのバックアップを `.claude/skills/{name}/SKILL.md.bak` に作成
- 指定された改善を適用した新しい内容で Edit
- 修正前後のトークン推定値を比較して表示

### `all` モードの場合

全スキルを解析して以下のランキングを出力：

```
## 全スキルトークン使用量ランキング

| 順位 | スキル名 | 推定トークン | 主な問題 | 削減余地 |
|------|---------|------------|---------|---------|
| 1    | analyze | ~2,800 tok | テンプレート過大、例示過多 | 高 |
| 2    | ...     | ...        | ...     | ...     |

**合計**: ~{N} tokens（全スキル常時ロード時）

最適化推奨順: {スキル名1} → {スキル名2} → ...
```

その後、最も削減余地の大きいスキルを詳細解析するか AskUserQuestion で確認する。
